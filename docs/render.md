# Deploy to Render

Use one Web Service. The production API serves both the React app and `/api/v1` from the same origin. The browser already calls `/api/v1`, and the login cookie is `SameSite=Lax`, so a second static site would break sign-in.

Do not add a Render static site, a second API service, or PostgreSQL for this phase.

## What Render runs

Root directory: the repository root. Leave Render's Root Directory field empty. The npm workspaces live at the root.

| Setting | Value |
| --- | --- |
| Runtime | Node |
| Build command | `npm run build` |
| Start command | `npm run start -w @news-india/api` |
| Health check | `/health` |
| Instances | 1 |
| Plan | `0.5c-512mb` or any larger paid web plan |
| Disk mount | `/var/data` |
| Disk size | 1 GB |

`render.yaml` records these settings. Render installs dependencies before the build command. `npm run build` builds the shared package, the API, and the Vite app. The start command runs the compiled API only. It listens on `0.0.0.0` and the `PORT` value Render sets. Do not set `PORT` yourself.

Node 20 or newer comes from the `engines` field in the root `package.json`.

## Environment variables

| Variable | Value |
| --- | --- |
| `NODE_ENV` | `production` |
| `DATA_PROVIDER` | `json` |
| `SESSION_SECRET` | Generated by Render (`generateValue: true`). Do not commit a secret. |
| `WEB_ORIGIN` | Render's `RENDER_EXTERNAL_URL`, for example `https://news-india.onrender.com` |
| `DEMO_DATA_FILE` | `/var/data/demo-data.json` |
| `DEMO_UPLOAD_DIR` | `/var/data/uploads` |

Leave `VITE_API_BASE_URL` unset. The built site then calls `/api/v1` on the same host.

On first start, if `/var/data/demo-data.json` is missing, the API copies `apps/api/data/seed-data.json` into it. Later starts keep the existing file. Only files under `/var/data` survive a deploy. Render's own disk documentation says a persistent disk can be attached to a paid web service, and only one instance can use that disk.

A free instance cannot attach this disk. Without the disk, the JSON file is wiped on every restart and deploy.

Sessions stay in process memory. A restart signs everyone out even when the JSON file remains.

If you add a custom domain, set `WEB_ORIGIN` to that exact `https://` origin and redeploy. The blueprint value is the `onrender.com` URL.

## GitHub to Render

1. Push this repository to GitHub, including `render.yaml`, `apps/api/data/seed-data.json`, and `apps/api/assets/fonts`.
2. In the Render dashboard, choose New, then Blueprint.
3. Select the GitHub repository. Render reads `render.yaml`.
4. If the service name `news-india` is already taken, change `name: news-india` in both the service and the `fromService` block, then sync again.
5. Approve the plan and the 1 GB disk. Render generates `SESSION_SECRET`.
6. Wait until the deploy is live and the health check passes.
7. Open the service URL. You should see the News India homepage, not a JSON error.
8. Open `/api/docs` on that same host for Swagger.
9. Sign in at `/admin/login` with a demo account from the root README. Create a draft, then refresh. The draft should still be there.
10. Trigger a manual redeploy. The draft should still be there because it lives on the disk. Sign in again, because the session does not survive the restart.

This repository was not deployed from this machine. A green local build does not mean the Render service is live. Check the Render deploy log and the public `/health` URL after the first deploy.
